## Big picture

`nfty` generates NFT-style asset collections by stacking layered PNGs. Each layer has one of three **kinds** (`LayerKind`). **Dynamic** + **static** layers = grayscale *value-maps* colorized at generation — recolor keeps each pixel's value/lightness, injects hue+saturation, so output space far larger than source images; dynamic **rolls** color per asset from weighted colorization, static applies **single fixed color** deterministically (no RNG). **Custom** layers = full-color RGBA composited **as-is**, never colorized (`Colorization` must be null).

**Domain = cooking metaphor — learn these eight terms before touching model:**

| Term | File ext | What it is | Owns |
|------|----------|-----------|------|
| **CookBook** | `.cbk` | *Uncooked Set* — top-level container | Canvas dims, collection metadata, per-Recipe selection weights |
| **Recipe** | `.rcp` | Complete template for one character/image *type* | Ordered layer stack (`layerOrder`, bottom-to-top — **the** paint order), incompatibility rules |
| **Ingredient** | `.igt` | One layer / trait-category | `kind` (dynamic/static/custom), colorization config, weighted variant images |
| **Variant** | *(inside `.igt`)* | One image + weight + name | Single PNG; not own file — hidden behind Ingredient |
| **Set** | `.set` or folder | Generated (cooked) output | Images + per-item metadata + rarity + seed |
| **Kitchen** | `.ktn` | Top-level *workspace* — names folder it sits in | Own identity only; membership **discovered** by scanning folder, never recorded (see `docs/superpowers/specs/2026-08-04-kitchen-design.md`) |
| **Menu** | `.mnu` | CookBook **flattened for runtime** — every weight, rule, colorization + art, no `.cbk` needed to roll/render | Its CookBook's weights, rules, colorization, canvas, plus art as one atlas or loose cells — nothing author edits |
| **Ticket** | *(no file — few hundred bytes)* | One rolled outcome: recipe id, one variant per layer, each colorized layer's rolled `(H,S)`, DNA | Nothing decoded — names selection, not pixels; `Nfty.Ticket`'s `AssetTicket` |

**"Model A"**: CookBook = container of whole-template Recipes; generating produces *mixed* Set by rolling Recipe per asset. (Older "Model B", Recipe = one layer, abandoned — ignore stray refs.) All images share one size, fixed by **CookBook canvas** — single source of truth for dims; every variant validated against it.

Every archive (`.cbk`/`.rcp`/`.igt`/`.set`/`.ktn`/`.mnu`) = **ZIP with `manifest.json`** + nested files; custom extension = renamed `.zip`, any unzip tool inspects. `.cbk` nests `.rcp`s nests `.igt`s — archive layers mirror domain layers. Every manifest implements `ISchemaVersioned`, version-checked in `ArchiveIo.ReadManifest` — one place all manifests read — so unreadable version raises `UnsupportedSchemaVersionException`, never silent misparse. Gate accepts `Schema.Oldest..Schema.Current`, refuses **newer**: future field this build can't see could change archive meaning. Used to demand exact equality → format unevolvable (bump `Current` by one orphans every archive). Reading older sound only via contract: **every field added after the floor schema is optional, defaults "absent"**. Rename, changed meaning, new *required* field breaks that → needs real migration, not bump. Additive optional field (like `TargetSupply`) needs **no** bump — `System.Text.Json` ignores unknown properties so older builds still read; bumping would make them reject. **Rise, 2026-09-25: `v2` is the floor.** `Schema.Oldest` moved 1→2 — v1 dropped by the author's decision, no v1 archives kept, `tests/fixtures/` regenerated at v2 (see its README) — so a v1 manifest is now refused exactly like a too-new one, named by `UnsupportedSchemaVersionException`, not silently misparsed. The bump carries two real fields: `.igt` gets `depth/{variantId}.dep` (front/back byte pair per pixel, row-major, absent = flat "paper"), and every manifest (`.igt`/`.rcp`/`.cbk`/`.mnu`) carries `partialAlpha` — **not authored, a listing cache**: stamped from the decoded pixels by every writer, recomputed by every reader that decodes pixels (`ArchivePeek` alone trusts the stored value, since it never decodes). The additive-field contract now reads **"every field added after v2 is optional"** — v1's own additions (`TargetSupply`, the palette) are moot, since nothing reads below v2 any more. Extensions → types via `Archives.KindOf`, rejects unknown extension rather than guess. `ArchiveKind` names **seven** kinds: four you author, **`Set`** (read, never hand-written), **`Sealed`** (`.tin`), **`Menu`** (`.mnu`, written by `nfty menu` from `.cbk`). Sealed export gets own extension, not `.set` of ciphertext: recipient double-clicking it — and any downstream tool ingesting `.set` — must be told before opening; file announcing itself only after failing to parse is worse than one whose name says so. Was left out once; omission cost more than it saved — `inspect` refused the one archive people hand each other, manual said otherwise, GUI's `OpenRecent` grew own `.set` extension compare to route around enum — exactly the second copy of mapping `TryKindOf` exists to prevent.

**Roll + render = two assemblies.** `Ticketer.TryRoll` (dependency-free `Nfty.Ticket`) decides every asset; `Generator` keeps only render, and `StackRoll.ForRecipe` — recipe preview — rolls through it too. Exactly one definition of order in which asset's layers consume RNG — see `Nfty.Ticket` under *Project layout*.

### Generation pipeline (`Generation/Generator.cs`)

Per asset: **roll recipe** (cookbook weight) → **roll each layer's variant** (ingredient weight) → **apply recipe's incompatibility rules** (re-roll on violation, bounded retry budget) → **colorize dynamic/static layers** (custom as-is) → **composite** → **hash DNA** → **dedup** (re-roll on collision) → **emit**.

- **Determinism:** single string seed drives **SplitMix64** RNG (`Rng.cs`), recorded in Set. Same cookbook + same seed ⇒ byte-identical output — across locales *and* CPU architectures. Two guards: every sort reaching output file uses `StringComparer.Ordinal` (default `OrderBy` sorts by current culture, silently breaks it), and `SeedHash.ToUlong` reads seed's SHA-256 with `BinaryPrimitives.ReadUInt64LittleEndian`, not native-endian `BitConverter` (would seed differently on big-endian CPU). Little-endian chosen so fix changes no output ever produced on the little-endian machines every Set was generated on.
- **DNA** (`Dna.cs`): SHA-256 over recipe id + each layer's variant id, plus — dynamic (rolled) + static (fixed) layers — `(H,S)` **quantized** per layer config (custom contributes variant id only). Quantizing folds explosive color space into uniqueness. Duplicate DNA ⇒ re-roll. Two distinct failures, never conflated: `RuleConflictException` when rules exclude *every* combination (space empty), `UniqueSpaceExhaustedException` when space real but smaller than `N`. Latter states true max, counted by `UniqueSpace.Count` (`Generation/UniqueSpace.cs`) — legal variant combos honouring rules × each dynamic layer's quantized `(H,S)` buckets; static/custom contribute one bucket each. **TOTALS ARE `BigInteger`, EXACTLY ONE LIMIT LEFT.** `DefaultEnumerationBudget` (1M) bounds the two things that genuinely enumerate — per-selection walk a ruled recipe needs, and set of distinct color buckets a colorization fills. Nothing bounds arithmetic (free: no rules → space factorizes into few multiplies). History: was one 1M cap for everything → five-million-asset book reported "more than 1000000" (computable in one multiply), every demo layer cost quantize re-tune. Splitting out `DefaultReportingCeiling` of `long.MaxValue` moved wall to 9.2e18, where **six layers of ten variants at 10°/10% quantize walks straight through** — `(10 × 360)^6 ≈ 2.2e21` — card printed constant where author read count. `BigInteger` has no wall → ceiling **gone rather than raised again**, `Add`/`Multiply` went with it, `SpaceCertainty.AtLeast` now names one cause: under-counted bucket set. Saturation can't happen; no test can pin it. **Count says which DIRECTION it's bounded — `SpaceCertainty`: `Exact`, `AtLeast`, `AtMost`, `Unknown`.** Was `bool IsExact`; three outcomes shared `false`, every surface rendered "more than N". Two really are floors (under-counted bucket set, saturated product). Third opposite: ruled recipe with more combos than enumeration budget can't be walked, so count reported BUDGET — book whose rules exclude all but 400 selections announced "more than 1,000,000", upper bound in lower bound's label. Now reports unconstrained product as `AtMost`, and `Unknown` when buckets it was built from were under-counted (product on under-count bounds truth in neither direction). Summing spaces → `UniqueSpace.Combine`, not `&=`: floor + ceiling = `Unknown`, bool can't express. `UniqueSpaceCount.Over(ids)` = that fold + saturating add, so `Generator`'s failure message and reports read one rule. `IsExact` survives as derived convenience, still means one thing: nothing gave up. `Add` saturates rather than clamp-after (add-then-clamp safe only while clamp far below `long` range). **Count is a promise:** exactly `Total` unique DNA must be generable, so bucket counting must track `ColorRoller.Roll` exactly — samples `Min + r*(Max-Min)` with `r ∈ [0,1)`, range **half-open** `[Min, Max)`; only degenerate `Min == Max` reaches endpoint. Off-by-one makes `Generate` throw self-contradicting "allows exactly N, but N were requested".
- **Extend** (`extend` command / `SetWriter.ReadExisting`): reopens existing Set, loads DNAs + numbering, rolls only new non-colliding assets, **recomputes rarity across whole collection** (rewrites existing items' `rarity`) since rarity collection-wide. Not second pipeline — same `Generator.Generate` with `existingDnas` / `startNumber` supplied. Keep new work behind that seam, don't fork generator.
- **Depth = `layerOrder` read second way, never stored field.** `Editing/LayerDepth.cs` projects it: **1-based position, dense, bottom-first — depth 1 paints first, sits furthest back**. `MoveTo`/`MoveBy` clamp (nudging top layer up = no-op UI shouldn't guard); `At` **throws** (asking depth 7 of five-layer stack = caller bug). Stored integer `z` rejected: makes two layers at one depth *expressible* (collision author wants prevented), needs absent-default on every read path for every floor-schema archive. List makes illegal state unrepresentable. Reordering preserves exact id set so `Validator` bijection survives every move — `Validator` gains **nothing** for depth; bijection rules already *are* depth invariant.
- **Reordering book = different collection, not re-render.** `Dna.Compute` sorts selections ordinally, so *given selection* hashes same in any order — why reorder safe for already-minted Sets, why depth must never enter hash. But `Ticketer.TryRoll` walks layers in `layerOrder` consuming one `WeightedRoller.Roll` each, so moving layer moves **which RNG draw reaches it**: on any layer with >1 variant selection itself changes. Same seed + reordered book ⇒ different pixels *and* identities. Only `set.json`'s `cookbookSha256` records it — why `extend` warns (stderr, never refuses) when book hash differs from recorded, and why null on either side = "cannot tell", not "differ".
- `Generator.Generate` runs `Validator.Validate` itself, throws on **any** problem — callers needn't pre-validate; `validate` command exists for humans, not required pre-step. `Validator` = single place deciding legal cookbook — must **report**, never throw (`validate` + GUI "what's wrong?" explain broken book). Check id uniqueness before any `ToDictionary` that throws on duplicate. Layer **name** must be unique within recipe: name = published `trait_type`, two sharing one merge into single trait + rarity bucket → collection ships percentages above 100. Reserved-name check for `"Type"` = special case of that rule.

### Project layout

- **`Nfty.Core`** — whole engine, organized by concern so Avalonia GUI consumes directly:
  - `Model/` — immutable domain records (manifests, variants, rules, colorization).
  - `Formats/` — ZIP + manifest readers/writers (`ArchiveIo` = shared low-level helper), plus `Validator`.
    - **Manifest ≠ what engine consumes.** `Loaded.cs` defines `LoadedCookBook`/`LoadedRecipe`/`LoadedIngredient`, each pairing `Model/` manifest record with eagerly-decoded `Image<Rgba32>` variants. `Generator` + `Validator` take `Loaded*`, never bare manifests — reading archive also pulls every PNG into memory.
    - **`ArchivePeek` reads manifest without decoding.** `Loaded*` = engine form, pulls every PNG; *listing* needs neither. `RecipeWeights.Count` + `Canvas` in outer manifest, so workspace row says "3 recipes · 1000×1000" without nested read. Same `ArchiveIo.ReadManifest` gate, schema check applies. **`ArchivePeek.CookBookTree` = same argument one level deeper** — `.cbk` + every nested `.rcp`/`.igt` as manifests, no image opened. `PeekedCookBook`/`PeekedRecipe` (`Formats/Peeked.cs`) returned: NOT `IDisposable` (nothing to own). Exists because whole class of question answered by nested manifests alone — how likely a selection, what a rule forbids, which variants a layer carries — and answering via `CookBookArchive.Read` pulls every variant PNG to look at few dozen numbers.
    - **All manifest JSON through `Json.Options`** (camelCase properties, enums camelCase strings). Default options silently break round-trips; reuse shared options for any new manifest field.
  - `Imaging/` — color conversion, color-spec parsing, value-map colorization, compositing (ImageSharp), `VariantPreview` — render of one Variant *exactly as generation would*. Rule lives here, not front-end: CLI `preview` + GUI Export must produce identical file; two copies is how that stops being true. Above: `StackPreview` (several layers at real depths, split around edited one) + `StackRoll` (whole Recipe rolled into that stack, generation's own draw order). Both build on `VariantPreview` + `Compositor`, add **no third rendering path**. "Exactly" literal: `PreviewLayer` carries unrounded rolled `(H,S)` **alongside** color spec, draws from former — every spec resolves through 8-bit RGB, rolled hue between two representable colors can't be spelled; rendering through string put preview ~0.25° off asset. Spec stays for humans to read + re-run.
  - `Generation/` — RNG, weighted roller, color roller, DNA, rules engine, orchestrator.
  - `Output/` — dual per-item metadata (standards-pure OpenSea `metadata/NNNN.json` + rich `nfty/NNNN.json` with dna/seed/rarity/per-layer color) + set writer + extend loader. `set.json` records `cookbookSha256` — hash of source `.cbk`, carried on `LoadedCookBook.SourceSha256` (populated by `CookBookArchive.Read`, **null for in-memory book never from file**) → `GeneratedSet` → `SetManifest`. Ties Set to exact archive that produced it; keep threaded through. **Set's item order = its NUMBER, never filename.** `SetReader` sorted `nfty/*.json` ordinally by path; stem padded to **four**, stops padding at 9,999, `10000.json` sorts before `9999.json` → collection past ten thousand loaded with last ten thousand in front. That's Set browser grid order — real bug. Fixed by sorting on number, not widening pad, deliberately: `metadata/NNNN.json` records own image path, renaming strands every published URL, and `extend` adds to Set whose files already named — collection-wide width leaves one Set holding two paddings.
  - **SPRITESHEET = FIFTH CONTENT AXIS, WATERMARK = SIXTH.** `Publish/SpriteSheet.cs` stitches assets into one image left-to-right then top-to-bottom **in Set's own numbering** — makes sheet addressable: cell `n` = asset `n+1`, engine indexing frames and reader counting rows agree with nothing recorded. Built **one asset at a time** (sheet = only large thing in memory) and **sequentially** (every asset draws into one image; `ParallelWork` contract rules that out). Real **pixel ceiling** (16,384 a side, separately on area — 1×400,000 strip small in area, still unopenable): sheet = one contiguous raster, 500 assets at 1000px in 23×23 grid = 529 megapixels, ~2 GB RGBA; refusal naming numbers beats `OutOfMemoryException` half a minute in. Missing asset leaves cell **empty, not failing sheet** — hole is information; closing gap renumbers every later frame. `NumberStamp` draws set number as **3×5 bitmap font, not typeface**: real font = `SixLabors.Fonts` beside ImageSharp pinned 3.1.11, plus grey anti-aliased ink on art with no grey. White over one-pixel black halo, reads on any ground; **draws nothing rather than clipping** — "12" cropped to "1" is wrong answer, missing stamp just missing. Both **export-only, never write back** — stamp destructive, export renders copy; **stamping BEFORE stitching**, so debug export's sheet carries same numbers as its sprites. **A sheet carries its own grid** (step 8): `SpriteSheet.WriteAsync` writes a `tEXt` chunk `nfty-grid` (`cols=8;rows=4;cell=64x64;count=29`, fixed key order, invariant) — omitted for an empty sheet — so a sheet handed on slices itself with nothing recorded beside it. `Publish/SheetGrid.cs` owns the text (`Parse` lenient on keys, strict on values; a count past `cols*rows` is malformed ⇒ absent), `Read` (via `Image.Identify`, no pixels), `Detect` (per axis the SMALLEST divisor whose cells no content run crosses — largest is always the whole side; wrong on a sprite with an internal gap wider than a cell, why the Rise page's grid row lets the author type one), `TryFromColumnsRows`/`TryFromCellSize` (non-throwing, one set of words), and `WriteInto`/`RemoveFrom` — which REWRITE the author's file via temp file + replace; a read-only file keeps the grid for the session instead. Other readers ignore the ancillary chunk, as the PNG spec requires.

- **`Nfty.Ticket`** — whole roll, extracted to dependency-free `net10.0` assembly: **zero** NuGet packages, no `Nfty.Core`/ImageSharp ref, so consumer needing only what a drop would produce (server, game engine) takes `Nfty.Ticket.dll` alone. `MenuBook`/`MenuRecipe`/`MenuLayer` (`Menu/MenuBook.cs`) = CookBook's weights, rules, colorization flattened + self-contained; `Ticketer.Prepare` resolves one into `PreparedMenu` (draw order + running weight totals fixed once, split `WeightedRoller.Prepare` makes, same reason), and `Ticketer.TryRoll` = **only roll of an asset in product** (`StackRoll.ForIngredient` still rolls one loose layer — no recipe, no absent chance, no rules) — decides whole asset (recipe, each layer's variant, each colorized layer's rolled color, DNA), consuming RNG touching no pixel, returning `null` when rules reject selection. `Generator` (`Nfty.Core`) projects `LoadedCookBook` into `MenuBook` (`MenuProjection`), calls `Ticketer` every roll, keeps only render — resolving accepted `AssetTicket`'s ids to decoded images, colorizing, compositing. `MenuArchive` (`Menu/MenuArchive.cs`) reads `.mnu` with **no imaging library**: atlas mode returns whole atlas PNG bytes + rect for cell, loose mode "rect" = whole image, so caller crops through one code path whichever mode wrote file. Writing `.mnu` needs source art decoded → stays in `Nfty.Core` — `Publish/MenuWriter.cs` — not here.
- **`Nfty.Model`** — Rise: pixel art → 3D. `net10.0`, `ProjectReference` `Nfty.Core` ONLY, **zero** packages, no glTF library; `Nfty.Core`/`Nfty.Ticket` never reference it (arrow one way, `AssemblyRulesTests` checks). `DepthMap` NOT redeclared — step 4's `Nfty.Core.Model.DepthMap` (in `Nfty.Ticket`); namespace `Nfty.Model` doesn't clash. `Riser.TryBuild(art, depth, options, source)` = one solid from one FINISHED image: solid = `Opacity.IsSolid` (**one** test, mixel's D1), partial alpha → `PartialAlphaException` naming item, checked BEFORE emptiness; nothing solid → `null` (batch skips + names, never fails — D5); takes `Image<Rgba32>`, never bytes (D6). Column z `[-(0.5+back), 0.5+front]` voxel units, +Z = viewer, image row 0 = TOP (highest Y). Faces = `GreedyRects` over keyed grid (equal front; separately equal back), one scan for every depth level. Walls = column interval MINUS neighbor's → **two** segments when neighbor sits inside both ends; one quad per pixel edge per segment, never merged. **Mesh = closed + consistently oriented, NOT strict 2-manifold**: greedy faces meet per-pixel walls at T-junctions (2×1 strip already fails "every edge shared by two triangles"), corner-only contact pinches four faces on one edge. `MeshChecks` refines axis edges to unit lattice segments, asserts each balanced by reverse + volume exactly `Σ(1+front+back)` + normals match winding; strict form only where no pinch. Don't "fix" test back to naive check. Pivot = named point of bounding box → origin (`BottomCenter` = X/Z center, min Y — centers SOLID, not paper), then × `VoxelSize`. Vertex shared only within its quad (normals/UVs differ per face); cross-quad dedup was measured (`RisePerfTests`, `Perf` table: vertex+index data is 99.57% of a 512px GLB, but only same-orientation quads can ever merge, and the fixture's own timing split shows wall emission dwarfing the merge step) and deferred rather than built — see `BACKLOG.md`. `StackDepth.Combine` = THE stack rule: every layer scanned for partial alpha BEFORE compositing, refuses by name (same one-solid-test D1 extended across the stack, `PartialAlphaException` naming the layer — a partial pixel can't hide behind an opaque one under it); composite via `Compositor`, then the **UNION rule** (2026-10-26; replaced "topmost solid layer's depth wins"): per pixel, front = MAX of the solid layers' fronts and back = MAX of their backs (no map = paper 0/0), so a layer can add relief but never carve what a lower layer built — the upper layer owns overlapping voxels. Result = `StackRise` (art + depth + per-pixel front/back owner), built with `StackFaces` (owner = topmost layer reaching the max, ties to the upper) and `StackPick`; the topmost solid layer's owner takes the finished art's own pixel, other owners recolorize their layer with the rolled color (`ColorRolls`, Set `LayerColor`), so a model of a cooked asset carries the colors that asset rolled. ### Sync/async pairs

Every I/O entry point has async twin; `Generate` also takes optional `IProgress<GenerationProgress>` + `CancellationToken` (`SetWriter.WriteAsync` reports `WriteProgress`). Split deliberate, preserve:

- **Genuinely async** (real awaits on stream/JSON/PNG-codec work): `CookBookArchive`/`RecipeArchive`/`IngredientArchive` `ReadAsync`/`WriteAsync`, `SetWriter.WriteAsync`/`ReadExistingAsync`. `ZipArchive` directory parsing has no async API — only per-entry I/O awaits.
- **CPU-bound, offloaded**: `Generator.GenerateAsync` = `Task.Run` over sync core. Roll/colorize/composite has nothing to await; exists to free UI thread. **No fake `async` in generation loop** — new work behind progress/cancellation params.

### Color specs

User-entered color must carry explicit prefix — `hex:`, `rgb:`, `hsl:`, `hsv:` (e.g. `hex:d6249f`, `hsv:322,83,84`). Missing/unknown prefix = **validation error, never guessed** (`Imaging/ColorSpec.cs`). Dynamic/static colorization takes only `H`/`S` from color; value/lightness from grayscale value-map.
