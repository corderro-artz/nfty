Exploration — the Kitchen's contents on Landing

Opening a Kitchen today gives a titlebar chip, a default save folder and reference layers in the editor. It does not let you open anything in it: KitchenContents.CookBooks is scanned on every open and has zero readers in the GUI. To open a book in the workspace you just pointed the app at, you navigate a file dialog back to the same folder.

All three treatments below are built from landing.html's own grammar — the same .slbl, .rlist, .rrow, .rico and .rzero the Recent list already uses. Ordered most standard first.

A — a Kitchen section stacked above Recent

most standard

The right column gains a second section, above Recent, using the identical row component. This is the pattern every editor uses (VS Code, Figma): workspace first, history second. Nothing new is invented — a second .slbl, a second .rlist, a hairline between them. Capped at four rows with a "more" affordance so the column cannot outgrow the left one.

B — one list, a segmented head

fixed geometry

The right column keeps exactly one heading and exactly one list, always. A segmented tray at its head switches between the Kitchen and Recent; with no Kitchen open the tray is replaced by the plain RECENT label in the same 20px slot, so the column's geometry never changes. The tray is the .seg grammar the Ingredient Editor and the Explorer already use, which is what ties this to the rest of the app. Costs one click to reach history.

C — a full-width workspace shelf

most distinctive

The two columns are left exactly as they are, and the workspace becomes a band beneath them — a horizontally scrolling shelf of cards. It borrows the Ingredient Editor's filmstrip vocabulary (.vcard: tile + name + meta, in a scrolling run), which is the strongest tie to the rest of the app. It is also the only option that changes the screen's overall shape: the band is absent with no Kitchen open, so opening one makes Landing taller.

Shared — an empty Kitchen

all three

A fresh workspace is not a broken one (KitchenContents.IsEmpty says so in as many words), so it gets the same .rzero treatment first-run Recent already has, pointed at the thing that fills it.

What each costs, honestly:

  • A — the right column now holds two lists, so it can outgrow the left one on a big workspace. Handled with a four-row cap and a "+N more"; that affordance needs somewhere to go (an Explorer-style workspace browser) or it is a dead end.
  • B — history moves behind a click while a Kitchen is open. Also the only option where the same slot means two different things, so the tray has to be unmistakable.
  • C — Landing changes height when a Kitchen opens or closes, which is the one thing the app's geometry rule otherwise forbids. Defensible (it is a mode change, like the "Kitchen: Studio" line the screen already grows today) but it is a knowing exception and should be recorded as one.

All three share the same engine work, so the choice is purely visual: a cheap PeekManifest in Core that reads an archive's manifest.json without decoding a single PNG — which is what lets every row above show real counts — plus KitchenItems on the Landing ViewModel, refreshed off IKitchenSession.Changed.
